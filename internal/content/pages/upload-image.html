Cadastro facial por envio de imagem

Importe uma fotografia JPEG ou PNG para registrar uma referência facial vinculada a subjectId, diretamente pelo backend da sua aplicação.

Não disponível na release comercial atual

Este contrato está implementado no Server PR #56 (Draft), ainda sem merge nem distribuição homologada. O pacote 0.1.11 atualizado em 12/11/2026 modificou apenas o Console e não disponibiliza estas rotas. É necessária uma futura release combinada do Server com Secure Core 0.2.2 ou superior. Este guia é uma prévia para planejamento de integrações, não uma garantia de disponibilidade.

Quando utilizar

O upload importa uma referência para comparação posterior 1:1, sem documento de identidade ou serviço externo. Ele não executa prova de vida nem confirma que a fotografia pertence à pessoa que a enviou. A verificação futura continua a utilizar POST /v1/verifications e a captura autorizada pelo SDK.

Requisitar a imagem somente mediante autorização e finalidade legítima. As imagens e templates permanecem isolados pelo tenant e pela aplicação na instalação Customer Hosted.

1. Enviar imagem facial

POST/v1/enrollments/imagesPrévia — não disponível no pacote 0.1.11

Execute a chamada somente no backend da aplicação, em conexão HTTPS, com Authorization: Bearer <application-key> e escopo enrollment:create. Use multipart/form-data, com exatamente dois campos:

CampoTipoRegras
subjectIdTextoIdentificador da pessoa, 1 a 128 caracteres, conforme validador do Server
imageArquivoJPEG ou PNG, até 4 MiB; de 80×80 a 4096×4096 pixels; máximo de 8 milhões de pixels
Shell · backend autorizado · prévia
curl --request POST \
  "$IFACEMATCH_API_ORIGIN/v1/enrollments/images" \
  --header "Authorization: Bearer $IFACEMATCH_API_KEY" \
  --form "subjectId=driver-123" \
  --form "image=@/secure/path/reference.jpg;type=image/jpeg"

Não configure manualmente o cabeçalho Content-Type: o cliente HTTP deve gerar o boundary do formulário. O Server valida o conteúdo real e normaliza a fotografia para JPEG antes de gerar a referência nativa. Fotos sem rosto ou com múltiplos rostos são recusadas.

2. Resposta de cadastro

201application/jsonReferência registrada
JSON · exemplo ilustrativo
{
  "id": "chk_example123",
  "subjectId": "driver-123",
  "status": "active",
  "enrollmentMethod": "uploaded_image",
  "livenessPerformed": false,
  "referenceImageSha256": "EXAMPLE_NORMALIZED_JPEG_SHA256",
  "imageAvailable": true,
  "createdAt": "2026-11-09T18:00:00Z"
}

Atenção: a resposta 201 indica referência cadastrada, não identidade confirmada. O hash refere-se à foto JPEG normalizada, não necessariamente ao arquivo original enviado. A resposta não contém embedding nem bytes da foto.

3. Consultar cadastro e recuperar a foto

GET/v1/subjects/{subjectId}/enrollmentEscopo checks:read

Retorna os metadados da referência ativa sem expor a fotografia.

GET/v1/subjects/{subjectId}/enrollment/imageEscopo enrollment:image:read

Retorna a fotografia normalizada com Content-Type: image/jpeg, Content-Disposition: attachment e Cache-Control: no-store. Requer permissão de leitura de imagem separada, que não deve ser concedida apenas para permitir verificação.

Shell · consultar metadados
curl --request GET \
  "$IFACEMATCH_API_ORIGIN/v1/subjects/driver-123/enrollment" \
  --header "Authorization: Bearer $IFACEMATCH_API_KEY"
Shell · recuperar JPEG com permissão explícita
curl --fail --request GET \
  "$IFACEMATCH_API_ORIGIN/v1/subjects/driver-123/enrollment/image" \
  --header "Authorization: Bearer $IFACEMATCH_IMAGE_READ_KEY" \
  --output reference.jpg

Use o mesmo subjectId em POST /v1/verifications para iniciar a verificação 1:1. A referência pode ser revogada pelo endpoint existente DELETE /v1/subjects/{subjectId}/enrollment, de acordo com as permissões da aplicação.

4. Validações e erros

StatusSignificado
400Multipart inválido, campos incorretos, formato/tamanho/dimensões não suportados
401 / 403Chave inválida, escopo insuficiente, licença ou autorização ausente
404Cadastro ou imagem não encontrada nas rotas de consulta
409Já existe cadastro ativo para o subjectId nessa aplicação
422Nenhum rosto, múltiplos rostos ou qualidade insuficiente
429Cota mensal de cadastro excedida
502Falha ao extrair a referência biométrica
503Motor indisponível ou Secure Core incompatível
Contrato em homologação

A política de qualidade (limiar nativo atual 0.25), a compensação para falhas parciais, a atualização combinada de Server/Core e os testes de rollback ainda devem ser homologados. Não automatize este endpoint em produção até a publicação de uma release compatível.
