Guia de upgrade e rollback

Atualize apenas componentes alterados após confirmar assinatura, compatibilidade e janela de manutenção. Não reinstale o sistema em um cliente já ativo.

Antes da atualização

  1. Confirme que o pacote está autorizado para a sua instalação e compatível com o Server, Console, modelos e SDK em uso.
  2. Registre as versões instaladas e valide o SHA-256 e a assinatura com a chave de distribuição fixada.
  3. Garanta backup protegido de arquivos de ambiente, units, dados e mecanismos de recuperação aplicáveis.
  4. Planeje o impacto: uma alteração só no Console não deve reiniciar o Server biométrico.
  5. Preserve os binários anteriores para permitir rollback.

Verificação somente leitura

Um operador deve inspecionar a versão assinada com o verificador oficial, usando o caminho absoluto de uma release já desempacotada e a chave pública instalada.

Shell · dry-run de pacote assinado
sudo /opt/ifacematch/releases/0.1.6/bin/ifacematchctl \
  install --dry-run \
  --release-dir /root/verified-release \
  --trust-public-key-file /etc/ifacematch/distribution.public \
  --trust-key-id ifm_distribution_prod_v1

Esse comando é ilustrativo do procedimento comprovado no piloto: substitua o diretório apenas por um pacote cuja origem foi previamente autorizada e validada.

Instalar e validar

Para um upgrade de componentes existentes, use o instalador assinado e específico da release aprovada, com pré-validação e rollback. O fluxo efetivamente testado no piloto 0.1.7 verificou assinatura no host, preparou a release em diretório paralelo, criou backup e alterou somente o ExecStart do Console.

Shell · disponibilidade interna do piloto
sudo systemctl is-active ifacematch-server
sudo systemctl is-active ifacematch-console

curl --fail --silent --show-error \
  http://127.0.0.1:8981/health

Revalide o login HTTPS e o fluxo funcional de MFA e API. A disponibilidade HTTP sozinha não prova que uma verificação facial produza decisões corretas.

Rollback seguro

Rollback exige preservar o executável anterior, verificar o backup e restaurar o unit ou release compatível. No piloto 0.1.7, o instalador contém rollback automático em caso de falha após troca do Console; os testes locais de restauração passaram, mas um rollback real no systemd ainda precisa de homologação em VM isolada.

Não repetir indiscriminadamente

O instalador bloqueia a mesma release quando já está preparada. Em caso de interrupção, avalie o estado dos arquivos e serviços antes de tentar outra vez. Não provoque falhas no ambiente do cliente para testar rollback.

Atualizações automáticas

A operação ifacematchctl upgrade --latest e o botão de atualização no Console são melhorias planejadas; ainda não estão disponíveis. O processo de release precisa primeiro de CI confiável, assinatura segregada, aprovação e testes de recuperação.
